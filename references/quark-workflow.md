# 夸克操作衔接

先读取本机安装的夸克官方 Skill；本文件只说明 HTML 流程怎样衔接，不替代官方命令契约。

## 连接检查

1. `doctor.mjs` 只查找安装位置和 Agent 通道，不读取账号配置或令牌。
2. 读取官方 `SKILL.md`，执行其要求的安装检查。
3. 用原始用户输入和当前对话统一的会话编号调用 `get-user-info`。可通过 `doctor.mjs --check-auth --session-input <原文> --session-id <编号>` 转发只读检查。
4. 未授权按官方 `references/auth.md` 处理。会员权益、notice、错误照官方要求展示；不要把环境识别失败解释成需要充值。

## 冻结范围

读取官方 `references/file-batch-organize.md`、`file-search.md` 和需要的内容理解说明。任务初始化在首次整理查询前完成。

按真实路径确认文件夹身份，完整展开用户范围内的子树。只用完整 Artifact 建清单，请求使用原始完整文件身份；不把搜索预览或命中总数当作源目录全集。

内容分析可能含 HTML 实体、引用或部分记录。核对名称/索引和覆盖情况后再写映射。不完整的分析不是完整方案，不因总体判断就给所有文件同一城市。

## 确认一致性

网页 `plan.json` 和官方 proposal 必须来自同一逐文件映射，身份、原父目录、原名称、目标和可选改名一一对应。

`plan.validation` 保存官方 check 指纹与 proposal 路径。最终按钮冻结本 Skill 内容指纹和官方指纹。文件、方法、路径、名称或验证信息改变都会使旧确认失效。

原目录内整理时，官方 proposal 的源和目标根都指向用户选中的真实目录。所有新目录都相对该根；不要省略目录参数而落入默认的「来自某 Agent」目录。

用户要求复制时先核实支持情况。只有自动检索式相册复制而不能提交固定清单/目录树时，不用它代替网页已确认方案。解释限制并让用户选择受支持方式。

## 执行结果

按官方最终协议结束、接续或撤回，不因目录存在就认定素材全部成功，也不违反官方规则另行复核或重提任务。

`status.mjs result` 只投影已保存的官方结果。服务端操作数可能含目录创建，不自动等同为文件数。精确成功文件数应来自明确文件计数或官方结果明细证据，不能减去猜测的目录数。

工作区留在用户本机。本 Skill 不收集、上传或分析账号令牌。
