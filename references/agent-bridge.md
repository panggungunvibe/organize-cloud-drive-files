# 网页向 Agent 发指令

## Codex 队列

初始化默认 `--bridge auto`，从真实进程的 `CODEX_THREAD_ID` 和 `CODEX_APP_RUNTIME_CLI_PATH` 或 PATH 定位 Codex。可显式提供 `--thread <当前会话ID>`、`--codex <CLI路径>`。服务启动时检查 `codex queue --help` 是否支持。

正式按钮先保存确认，再调用：

```text
codex queue --thread <绑定的现有会话> --message <含方案路径和指纹的确认消息>
```

退出成功只代表排队成功，页面显示“已发送，等待 Agent”。Agent 回写 `running` 后才显示真实执行。不使用 shell，不把浏览器自由文本拼成命令。

该入口依赖本机 Codex 版本及会话可达性。不伪造 Agent 环境，不创建新会话冒充当前 Agent，不存账号令牌，不由网页服务器执行夸克写操作。

## 手动降级

没有队列、会话信息或选择 `--bridge manual` 时，网页保存确认并提供复制指令。用户发到当前 Agent 后读取确认执行。页面明确说明需要发送一次，确认已保存不代表 Agent 已收到。

发送状态未知时不自动重发。先在原会话核对 requestId 是否已处理，再按真实任务记录决定后续。

## 本地界面

只监听 `127.0.0.1`，最终确认要求本机 Host、同源请求和会话令牌。公共目录只放页面及缩略图；私有方案、确认和原始响应不暴露为静态资源。

拒绝重复确认、方案改变后沿用旧确认，以及用新方案覆盖已有执行或未知结果的工作区。停止服务不撤销网盘操作。
